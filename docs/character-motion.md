# Общие события движения и звуки персонажей

Система подключается движковым `scripts/newviso/engine_game.ysc` во всех проектах.
Ручная установка аудио в `FirstFPS` или другом проекте больше не требуется.

## Владельцы данных

- `character_motion.ysc` — общий автомат событий физического движения.
- `character_support.ysc` — пары опоры с временем жизни на физическом такте. Кадр отрисовки без нового физического шага не теряет опору.
- `gameplay/character_motion.ysc` — движковый адаптер игрока. Читает фактическое тело из `engine_player.physics_entity`, независимо от владельца управления `shared/project`.
- `application_characters.rs` — наблюдение нативных NPC. Передача управления реакциям Endorphin не обрывает наблюдение взлёта/приземления.
- `application_character_audio.rs` — один обработчик контактов на персонажа, после обновления анимации.
- `application_script_commands/audio/characters.rs` — предзагрузка и воспроизведение через действующий аудиопровайдер.

Параметры находятся в `Shared/Content/config/engine/runtime.defaults.xml`, группе
`engine_character_motion`. Проект переопределяет только данные: материал поверхности,
порог определения походки и параметры опоры. Привязка не содержит проверок имени проекта
или модели.

## Поведение

1. Адаптер использует физическую позицию и скорость, а не запрос движения и не интерполированную позицию отрисовки.
2. Скорость относительно движущейся опоры отличает движение персонажа от перемещения платформы.
3. Общий автомат публикует `character.locomotion.changed`, состояния походки, `character.jump`, `character.fall`, `character.land` и совместимые события анимации.
4. Аудио шага следует контакту отображаемой стопы. Пока анимация/кости не предоставляют такие контакты, используется ограниченный резервный расчёт по физически пройденному расстоянию.
5. На контакт публикуется одно `character.footstep`, с `actor_id`, `entity`, `locomotion`, `surface`, `position`, `step_index` и `contact_source`.
6. Начальное появление, телепорт, кратковременное отсутствие физического обновления и удаление тела не создают искусственные шаги/приземления.
7. При физической реакции без права управления ходьбой NPC не создаёт шаги от скольжения тела. Наблюдение приземления сохраняется.
8. Банк предзагружается один раз на сочетание источника и поверхности. Неактивные обработчики персонажей освобождаются.

Общие события адаптера передаются через движковую очередь с `script_echo:true`.
Адаптер не вызывает их локально перед отправкой, поэтому модуль движка и модуль проекта
получают по одному уведомлению. Публикуемые контакты помечены `audio_handled:true`:
совместимый `installCharacterAudio` пропускает уже озвученные события.

`FirstFPS` сохраняет проектный псевдоним `game.player.footstep` и отменяемые события ввода.
Собственные счётчики шагов и канонические события движения из FirstFPS/NorthYankton удалены.
Контроллеры FirstFPS, Island, ProceduralMap и NorthYankton используют общий расчёт опоры.
В NorthYankton идентификатор физического тела и снежная поверхность теперь явно заданы
в runtime-данных.

## Проверка

```text
cargo test --offline -p newviso-runtime -p newviso-scene --lib
node scripts/verify_character_motion.mjs
cargo build --offline --release -p newviso
python scripts/verify_character_motion.py --controller shared --npcs
python scripts/verify_character_motion.py --controller project --npcs
python scripts/verify_character_motion.py --controller project --firstfps --npcs
python scripts/verify_endorphin.py --scenario default --actor-index 0 --run-tag motion-render
python scripts/verify_endorphin.py --scenario default --actor-index 1 --run-tag motion-closeout
```

JS-проверка включает разные частоты кадров, опору/ContactEnd, движущуюся платформу,
сброс после телепорта и удаления тела, начальное появление, доставку событий и
конфигурации FirstFPS, Frostline, Island, MadMaxWasteland, NorthYankton, ProceduralMap,
VehicleTest и WeaponLab.

Нативный сценарий не устанавливает проектный звуковой обработчик. Он проводит игрока
через ходьбу, быстрый бег, прыжок и приземление и проверяет события двух NPC на разных
импортированных скелетах. Параметры физического мира одинаковы в вариантах управления,
чтобы проверка сравнивала именно владельцев управления.

Итоговые результаты и хеш проверенного executable записываются в
`.newviso/cache/character-motion-acceptance.json`. Наличие PNG в сценарии означает
только сохранение снимка окна и не считается доказательством качества изображения.

## Исправление текстур первого лица

Видимые части тела уже имели базовые текстуры и готовые GPU-материалы. Изображение
терялось в deferred lighting: камера помечает поверхность, исключённую из отражений,
значением `normal_twiddle.a = -1`. Старый встроенный SPIR-V считал такое значение
отсутствием геометрии и отбрасывал пиксель. Вместо тела оставался однотонный фон.

GLSL уже содержал правильную проверку `abs(normal_twiddle.a)`, но упакованный
байткод и установленный `vulkan-renderer-0.37.7-release.dll` оставались старыми.
Deferred-шейдер пересобран из существующего GLSL, провайдер собран и обновлён.
На сопоставимых снимках FirstFPS после исправления видны одежда и кисти.

Проверка `PluginsSrc/VulkanRenderer/newengine-modules-render-vulkan-ash/tests/verify_compiled_coverage.py`
исполняет выражение проверки валидности из SPIR-V для положительной, отрицательной
и нулевой метки. При переданном `--provider` дополнительно проверяется, что этот
байткод действительно встроен в DLL. На старой DLL проверка отрицательной поверхности
падала; на обновлённой проходит.

Нативный сценарий `--firstfps` использует настоящие `fps/game.ysc`, проверяет общие
звуки игрока и двух NPC, стартовую регистрацию модели и полную нативную таблицу
материалов. Примитивный пол тестового двора явно включается вместо отсутствующих
YBN-секторов Lifeinvader. В FirstFPS модель и начальная анимация теперь регистрируются
в `on_start`, чтобы участвовать в стартовой загрузке ресурсов.

При `NEWVISO_SCENE_MATERIAL_DIAG=1` полный нативный snapshot содержит
`scene.main_view_geometry.instances[].material_bindings`: слот, имя материала,
базовую текстуру и готовность GPU. Облегчённый покадровый payload скриптов эту
диагностику не передаёт. Проверка читает полный snapshot.

## Результат проверки 25 октября 2026

| Проверка | Результат |
| --- | --- |
| Runtime | 160 прошли, 1 пропущен |
| Scene | 171 прошёл, 3 пропущены |
| VulkanRenderer | 152 прошли, 3 пропущены |
| Скрипты и конфигурации | 270 проверок; 8 активных проектов |
| Нативные сценарии | 5 из 5 |
| Изоляция Cargo | Прошла |
| Проверки whitespace движка и провайдера | Прошли |

Нативные сценарии: общий контроллер с двумя NPC, проектный контроллер с двумя NPC,
настоящий FirstFPS с двумя NPC и материалами первого лица, затем два скелета ragdoll
через GPU и CPU. У игрока и каждого NPC в сценариях движения проверены одно событие
прыжка, одно приземление и реальные контакты шагов. В проверенных падениях сохранены
длины и масштаб костей, восстановление и единственный перенос оружия.

Итоговый отчёт: `.newviso/cache/character-motion-acceptance.json`.
Он содержит хеши executable, VulkanRenderer и Bullet, хеши проверенных исходников,
события по персонажам и исходные отчёты сценариев. Всего прошли 483 модульных теста;
7 тестов остались явно пропущенными.

После изменения GLSL необходимо пересобрать соответствующий упакованный SPIR-V и DLL.
Проверка `--firstfps` теперь сначала проверяет signed-coverage контракт байткода,
действительно встроенного в установленный провайдер.

## Оставшиеся ограничения

Полноценное активное равновесие Endorphin остаётся незавершённым.
Общий архитектурный gate сохраняет пять существующих замечаний о конкретном
формате аудио в исходниках движка. Этот результат не объявляет завершённой
полную систему Endorphin или устранение всей архитектурной задолженности.
